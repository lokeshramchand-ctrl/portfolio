# Critique — 2026-07-26

Self-review of the Next.js rebuild as it stood at commit `8dc98e3`. Two passes, as
requested: a harsh creative-director read of the actual code, then a recruiter-journey
walkthrough. **Honesty note up front:** no browser tool is available in this session —
this review is a close reading of the actual markup, animation logic, and CSS, not a
lived visual experience. Anything that depends on _feel_ (scrub smoothness, timing,
whether the SVG building actually reads at a glance) is flagged as unverified, not
rated. Claiming otherwise would be worse than saying so.

## Pass one — creative director

**Critical**

1. **No mobile navigation exists.** `Nav.tsx` renders the link list as
   `hidden md:flex` with no fallback — below the `md` breakpoint there is no way to
   reach Work/About/Contact/Blog except scrolling. On a portfolio, this is the single
   worst thing a recruiter on a phone can hit in the first five seconds.
2. **`About`'s service blocks are exactly the "generic card" pattern the brief calls
   out to avoid** — `rounded-lg border border-paper-500/10 p-6`, repeated three times,
   indistinguishable from a SaaS features grid. The construction metaphor gives an
   obvious alternative (services _are_ structural systems) that isn't being used here.
3. **No structured data, no canonical URL.** For a portfolio meant to represent someone
   professionally, `Person`/`WebsiteStructured data and an explicit canonical are table
   stakes, not polish — currently absent entirely.
4. **Social preview image is a reused headshot, not a designed card**, and its declared
   `1200x630` dimensions were never verified against the actual file (`og-image.webp` is
   just `profile2.webp` renamed). A shared link currently either shows a distorted photo
   or an untested crop.

**High impact**

5. **No magnetic-button interaction anywhere**, despite it being explicitly requested
   and despite `CLAUDE.md`'s own architecture notes referencing the old site's
   `MagneticEffect.vue` as prior art that was never carried forward. The CTAs currently
   just `hover:scale-105` — competent, not premium.
6. **No scroll-position indicator.** Explicitly requested, and genuinely useful here
   given the site has one unusually long pinned section (400vh) where a visitor could
   otherwise lose their sense of "how much is left."
7. **No skip-to-content link.** The header is fixed and present on every route; keyboard
   users have no way to bypass it. This is a real accessibility gap, not a nice-to-have.
8. **The construction SVG is honest line-art, not clip-art, which is good** — but it is
   also fairly literal (a building elevation, drawn as a building elevation). It clears
   the brief's bar ("not literal construction clip art") but doesn't yet reach "artistic
   transformation." Flagged, not fixed this round — a full re-conception is a bigger bet
   than can be responsibly made without seeing the current version render first.

**Medium**

9. The Works section subhead — "Two projects, walked through like rooms — not
   summarized like cards" — explains its own device to the visitor, which undercuts it.
   Show, don't narrate the metaphor.
10. Typographic motion is limited to the Hero's typed line; nothing elsewhere uses
    character stagger or masked reveal, so the "premium interactions" list is
    under-delivered outside Scene 1.
11. CTA hierarchy is _fine_ but not distinctive — solid amber pill for primary, text
    link for secondary, repeated identically in Hero, Works, and Contact. Not broken,
    just safe.

**Future ideas (not implemented this round)**

- A dedicated project detail route per case study instead of a single-page "floor."
- Revisit the SVG building for a less literal treatment once it's been seen rendered.
- A light theme was **not** added — the "Site & Blueprint" palette is a deliberate
  single dark theme carried over from the original site's brand direction, not an
  oversight. Revisit only if there's a real reason to support light mode.

## Pass two — recruiter walkthrough (code-level, unverified visually)

- **0–2s:** dark screen, typed line, reveal — reads well as a hook _in the markup and
  timeline logic_. Can't confirm the pacing feels right without seeing it.
- **Immediately after, on mobile:** dead end — see Critical #1. A recruiter skimming on
  a phone during a commute is a realistic, common case this currently fails outright.
- **Construction scroll (Scenes 2–5):** 400vh of pinned scroll with no progress
  indicator (Critical/High #6) — risk of feeling long with no sense of how much remains.
- **Projects:** only two, both real — inherent to the person's actual work, not a
  content gap to paper over with invented projects.
- **Testimonial:** one real quote, presented plainly — appropriately modest for the
  amount of real material available; not overstated.
- **Contact:** clear, single CTA, real contact info — no notes.

## What's being fixed now

Critical #1–4 and High #5–7: all fixed this session. #8 (the SVG building's literalism)
and the Medium items are logged in `docs/roadmap.md` under "Next up" rather than
attempted blind.

### Resolution log

- **Critical #1 (no mobile nav):** fixed — hamburger + full-screen overlay menu.
- **Critical #2 (generic service cards):** fixed — replaced with a "systems schedule"
  list treatment tied to the construction metaphor.
- **Critical #3 (no structured data / canonical):** fixed — Person + WebSite JSON-LD
  sitewide, BlogPosting JSON-LD per post, explicit canonicals on `/`, `/blog`, and every
  post.
- **Critical #4 (reused headshot as social image):** fixed — `opengraph-image.tsx`
  generates a real, on-brand 1200×630 card via `next/og`. Brand fonts didn't survive the
  renderer (see `docs/decisions.md`); it currently ships with a default sans fallback.
- **High #5 (no magnetic buttons):** fixed — `useMagnetic` hook applied to the Hero,
  Contact, and per-project CTAs.
- **High #6 (no scroll progress indicator):** fixed — thin fixed top bar driven by
  ScrollTrigger, reduced-motion safe.
- **High #7 (no skip-to-content link):** fixed — landed together with #3 in the same
  layout.tsx edit.
